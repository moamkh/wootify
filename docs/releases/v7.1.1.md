# Wootify v7.1.1

Released 2026-10-11. Backend, frontend, and root version files are aligned at
7.1.1. The tag contains focused commits for the following problems.

## Changes

1. Bale PV forwards: modern forward wrappers were confused with quoted replies
   or empty service notices. Preserve the original media and add a readable
   forwarding source label when available.
2. Eitaa update delivery: bounded, process-local history scans could miss
   messages and could not reliably serialize entity dictionaries for retry.
   Consume the difference stream, encode entities as JSON-safe records, and
   commit each batch and cursor together before acknowledging it. The shared
   inbound worker handles delivery retries and ordering across restarts.
   Polling uses the server's foreground cadence, not a hardcoded history-scan
   interval. Expired sessions and unrecoverable cursor gaps become visible errors.
3. Contact routing: outbound Eitaa contacts without an instance map could not
   be resolved. Verify exact phone matches, retain instance-owned routes, reuse
   account contacts by normalized phone, and repair older phone-less duplicates
   using verified local aliases. Never write a managed identifier over WhatsApp's
   identifier or remotely merge/delete a contact. Preserve meaningful names.
4. Replies: normalize nested Eitaa reply headers and avoid selecting a parent
   or outbound mapping from another peer/conversation.
5. Locations/contact cards: produce readable Google Maps links and contact
   details rather than treating non-downloadable media as static attachments.
6. Deletions: update the mapped original Chatwoot row using explicit upstream
   deletion events. Unknown-peer deletions cannot overtake failed originals;
   ambiguous peer resolution fails closed.
7. Outbound media: send each file first and text once afterwards, with per-part
   durable checkpoints and stable Eitaa random IDs. Partial retries skip parts
   that were already acknowledged. Caption edits/replies map to the text part.
8. Failed deliveries: require a send acknowledgement, retain private failure
   notes, set Chatwoot's failed status for native Retry, and set sent on success.
9. Connection visibility: optional Eitaa Connector status conversation in the
   configured inbox, with a UI toggle and outbound read-only guard even after
   reporting is disabled.

The release also includes commit 530abb0, the earlier frontend protection against
remote installations using a localhost backend URL.

## Database and rollout

No schema migration is added. The existing inbound_event_retries,
instance_runtime_state, contact maps/aliases, and message mappings are reused.
No deployment, database deletion, or session reset is performed by publishing
this release. Back up the live database/configuration before a later rollout.

## Known boundaries

- Initial adoption establishes a current upstream cursor; old history is not
  automatically imported.
- updates.differenceTooLong and channel gaps require explicit history/channel
  recovery rather than silently resetting the cursor and dropping messages.
- Native reply quotes require a previously mapped parent in the same
  conversation. No guessed cross-conversation parent is used.
- Live locations are coordinate snapshots, not continuously updating maps.
- Stable random IDs and per-part checkpoints reduce duplicate retries; a send
  acknowledgement does not prove the customer received or read the message.
- Evolution API's voice-delivery fixes belong to the separately versioned
  Evolution fork and are not included as Evolution source in this repository.
