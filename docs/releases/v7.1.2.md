## Inbox conversation behavior

Existing inboxes can be switched at any time in the instance editor:
Configuration → Chatwoot → **Conversation behavior**. Save the instance after
changing **Reopen resolved conversation**.

- Enabled: the next new incoming message reopens the resolved conversation in
  that inbox, or uses an already unresolved conversation if one exists.
- Disabled: it creates a new conversation after resolution. This is the default
  for newly configured instances; existing saved legacy choices are preserved.
- Saving does not immediately reopen anything and does not merge/delete history.
- Enterprise Sales/Support and Telegram dynamic routes have independent inbox
  controls. Standard Telegram now correctly saves its inbox fields/settings too.
- WhatsApp inboxes whose delivery is handled directly by Evolution are not
  controlled by this Wootify option.

The current configuration is read during delivery. Pending queue jobs follow
the saved policy on their next attempt. The existing encrypted instance config
stores validated `reopen_conversation_by_inbox` overrides; partial patches keep
other inbox settings and credentials.

## Reliability and historical mapping safeguards

- The PV adapter bridge now honors the setting instead of always skipping
  resolved tickets. Remote status checks cover missed resolution webhooks.
- New tickets receive their own local mapping; old messages retain their
  original ticket for subsequent edits, deletes, and reply lookups.
- Already delivered duplicate events and edits are checked against historical
  mappings before choosing/reopening a ticket.
- Explicit `open` requests fail back into delivery retry handling instead of
  silently proceeding after a failed reopen request.
- Enterprise flows distinguish missing tickets from resolved tickets, preserve
  the first incoming message after resolution, and do not reopen a route's old
  inbox after it has been relinked.
